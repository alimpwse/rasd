# RASD — Field Notes 0.15

A camera-first PWA for construction site observations. English interface with Arabic and mixed-language content. Static HTML/CSS/ES modules: no runtime libraries, accounts or backend for photos. The published URL is public; each device keeps its own local notes.

## Capture and image quality

- Live preview opens on launch where permission allows. The shutter opens the phone's native capture interface through a user gesture. Import from Photos is also available. Preview frames are never used as full-quality photos.
- The supplied original Blob is stored unchanged. JPEG, PNG, WebP and browser-decodable HEIC/HEIF are accepted, up to 25 MiB and 80 MP. Undecodable formats are rejected rather than silently converted.
- Edited photos share and download as full-resolution JPEG within the selected crop. Quality starts at 0.92. Large files retry at 0.84 and 0.74 to aim for 8 MiB while preserving dimensions. The information strip adds height and the overlay keeps the photo dimensions.
- JPEG compression can slightly change pixel values. Edited exports omit original HDR, EXIF metadata and RAW data. iOS controls resolution and the representation provided by its picker; this PWA cannot guarantee Apple Camera's computational processing, ProRAW or 48 MP capture.
- Save original downloads the exact supplied file. Devices may run out of canvas memory; export reports a failure and the original can still be saved/downloaded. For unchanged delivery through WhatsApp, save to Files and send as a document; ordinary photo sharing can be recompressed by WhatsApp.

## Field workflow

- Create a project once, then select it above the viewfinder or inside the note. The active project is remembered across launches on this device. Names from old notes are also offered. GPS and addresses are never copied from an earlier project/photo.
- Every photo opens in Edit, with photo markup and the note, project, category and editable GPS address together. Mobile uses a single scrolling surface; wide screens place them side by side. Save/Share stay fixed. GPS detail and technical export metadata are kept out of the main flow. Preview shows the complete exported record and does not add annotations. English/Arabic text direction follows the content.
- Set defaults in Settings for date, time, place, project, category and/or note: Below photo (default), On photo, or Off. Each field is optional. Defaults persist locally and are copied into new photos; saved notes keep their settings. Open the settings icon in a note and use Apply defaults to this photo to deliberately update that photo. Export/backup actions for the open photo also live in Settings. Preview and exported JPEG use the same rendering logic. Time uses h:mm AM/PM (e.g. 9:05 AM), without KWT, across stamps, messages and the library. Time is when the record was created, in Asia/Kuwait; imported photos do not claim their EXIF capture date.
- GPS adds coordinates and accuracy. Photon/OpenStreetMap suggests area/block/street in Kuwait after capture, with manual edits retained. Only coordinates are sent to `https://photon.komoot.io/reverse`; photos, projects and note text are never sent. Disable Automatic Kuwait address in Settings to prevent these requests. Lookups use a 200m search radius, reject points beyond 250m and GPS accuracy worse than 100m, and only extract explicitly labelled block numbers. Missing fields stay blank. Requests are serialized with at least 3 seconds between attempts; successful results are cached on-device (100 coordinate keys, 7 days). Offline lookup uses a matching cached result or leaves manual fields usable. No background tracking. The free public provider permits moderate use but has no uptime/coverage guarantee: https://github.com/komoot/photon. This is a nearby address suggestion, not official PACI coverage.
- Save locally in IndexedDB. Notes has project/category filters, search, newest/oldest order and Kuwait-day groups. Use the ••• button on a note for Edit/Delete, or Delete in the saved note header. Deletion requires confirmation. Library options contains backup/restore. Safety and Site Cleanliness categories are included; old notes without a category remain Uncategorized. Settings → Categories supports adding and renaming English/Arabic labels and selecting a default for new notes. Stable IDs preserve membership when renaming; current labels are used for filtering/search, printing, sharing and backups. Old `housekeeping` IDs are retained with the clearer Site Cleanliness label. Existing notes and backups remain compatible and default to no stamp.
- Share JPEG with independently selected message fields: project, category, note, date, time, area, block, street and Maps link. Settings → WhatsApp message fields controls defaults for new photos; Apply defaults to this photo updates an open photo explicitly. Copy selected text or save a file if a destination ignores a caption. With every field off, no text is attached and Copy does not overwrite the clipboard. Printed image fields remain independent.
- Back up/restore JSON with original bytes, thumbnail, annotation vectors and stamp/export settings and category. Import merges new IDs and preserves existing notes. Limits: 64 MiB/500 notes per backup, 200 annotations per photo. Single-note backup is available. Full v2 backups additionally include all Settings (including theme), unused/renamed categories and their default, all project presets and the active project. Full restoration replaces saved device data after confirmation; v1 note-only backups still merge.
- Offline shell and explicit version update. Clearing site data can erase local notes; keep backups outside the app. Drafts save automatically to IndexedDB. Changes still being written can be lost if iOS closes the process; wait for “Draft saved”. Clearing browser storage can erase drafts too.

## Save & Next rounds

The editor retains Save note and Share and adds Save & Next. After a successful durable save, Save & Next returns to the camera with the saved note's project/category ready for the next capture or import. Tap the shutter to open the phone camera; a native picker is not opened after asynchronous work because Safari user activation may expire. The current camera controls show the pending next-note context and End round. A cancelled picker or undecodable file retains the context, while a successfully opened new photo consumes it. Changing the camera project changes the pending project. End round and reload return to the configured category default; no extra persistent preference is created.

The next note starts with a fresh ID/date/GPS request, blank description/address and one new unmarked original, plus current export/stamp defaults. No empty note is created before a photo exists. If GPS/address changes arrive during commit, Save & Next saves the latest revision before advancing. Save errors, draft conflicts and the cross-window restore gate keep the editor open. Ordinary Save note still stays in the editor. The workflow has automated mobile/landscape, repeated-tap, cancellation, late-GPS, failure and restore-gate checks; physical iPhone acceptance remains required.

## Selected-note PDF reports

Notes → Select → choose notes → Create report. Search and collapsed project/category/order filters remain usable during selection; Select all results affects only the visible results, while a count identifies selected notes outside the current filter. Cancel clears selection without changing the library.

Reports are generated entirely on-device, including offline after the shell is cached. Setup offers a title, oldest/newest ordering, location/map and date/time switches, and the complete selected-note list. Reports read saved versions, with a warning for unfinished drafts. Every photo gets its own A4 page, with all markup, category/project and the full description on the first page plus continuation pages as needed. Coordinates are only in the clickable Google Maps link, not printed. Image stamps are omitted inside the report to avoid repeating the report metadata.

Cropped photographs are embedded at their full pixel dimensions using lossless RGB Flate compression, with an uncompressed fallback when CompressionStream is unavailable. The report text is a high-resolution raster layer for consistent IBM Plex Sans Arabic shaping; it is not selectable/searchable PDF text. In-app previews use separate small images. Progress can be cancelled; stale results never replace a newer PDF. Save PDF and Share PDF act on a prepared file, retaining the user gesture for the share sheet. If file sharing is unavailable, save to Files and attach the document in WhatsApp.

Limits: 20 saved notes, 50 photos, 100 MiB final PDF. Oversize selections fail as a whole, never omit photos. Full-resolution files may be large and remain subject to device memory. Generated PDFs are temporary until downloaded/shared and are not added to note backups. PDF syntax, original cropped pixels, Arabic wrapping/continuations, map links, cancellation, offline generation and UI flows are covered by automated tests; actual Safari/WhatsApp sharing still needs an iPhone acceptance check.

## iPhone acceptance still required

Open the public HTTPS URL in Safari → Share → Add to Home Screen. Allow camera and precise location. Check Offline ready. Take a real site photo and compare it with Apple Camera at the same settings, including fine detail and low light. Test HEIC, native camera cancellation, portrait/landscape, locking and returning, Photos import, Arabic editing, offline save/reopen, backup restoration, and actual WhatsApp delivery. Automated Chromium tests do not validate Safari capture, HDR or WhatsApp behavior.

## Development and checks

Source is served directly from `dist/`; no install/build step.

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
node --test tests/*.test.mjs
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node tests/browser.mjs
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node tests/races.mjs
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node tests/quality.mjs
```

Tests cover backup integrity, legacy notes, Arabic, project persistence, native file-input path, full 4032×3024 JPEG dimensions and a PNG pixel comparison for crop geometry, appended-strip dimensions, unchanged original bytes, stamp persistence, offline use, denied preview permission, storage-full handling and delayed GPS/decode races. Mobile/tablet/landscape layouts are checked in Chromium. Service worker cache: `rasd-shell-v17`; IndexedDB v5 preserves mixed media notes and blocks older photo-only writers.

Design reference: [Halide](https://halide.cam/), for camera-first composition and restrained controls. Latin UI uses the system font (SF Pro on iPhone); Arabic uses bundled IBM Plex Sans Arabic 400/500/600 with an Arabic unicode range. Font assets are precached and loaded before canvas measurement/export.

Safari navigation recovery (0.2.1): cache the canonical root, reject redirected precache requests, read only the active shell cache, and auto-activate the repair for v1/v2 without reloading an open draft. The HTTP regression server reproduces the production 307 from `/index.html` to `/`; tests cover automatic recovery with saved data and offline navigation retained. Run `node tests/sw-navigation.mjs` with the same Playwright environment.

UX references for 0.3: CompanyCam project organization and Fieldwire chronological photo grouping/action menus. `tests/editor-layout.mjs` verifies portrait-photo tools are visible and hit-testable at 320/375/390px, landscape and tablet, plus tab keyboard navigation and read-only Preview. `tests/library-browser.mjs` verifies filtering, sorting, date groups, deletion/cancellation, reopen scroll reset and backup visibility.

0.4 validation: `tests/settings-browser.mjs` exercises defaults across reload, immutable existing-note settings, explicit apply-to-photo, category filtering, delayed address results/manual edits, address disable and provider failure. Unit tests cover Kuwait address parsing, local caching/offline fallback, poor GPS, preference storage errors and category backup compatibility. Three real Photon samples in Salmiya, Rabiya and Zahra returned area/block/street; this is not a Kuwait-wide coverage audit.

`tests/address-races.mjs` covers responses arriving after closing a draft, during a save, or after disabling lookups, plus manual edits across a GPS refresh. Sharing tests verify both photo-only and text-included payloads retain user activation.

0.5 validation: `tests/categories.test.mjs` and `tests/categories-browser.mjs` cover persistent category management/defaults, duplicates and malformed data, stable IDs across rename, custom names in backup/print/share/search, fresh-device restore and existing-note isolation. Note backups include names for used categories; unused catalog entries and the default remain device preferences. Restore adds missing definitions and preserves existing local names/defaults.

`tests/category-recovery.mjs` delays initial catalog recovery until a photo has been saved/prepared, then verifies that the recovered category name appears in both the printed export and share caption and the note stays marked as changed.

0.6 framing (superseded by 0.7 for new capture defaults): initially offered Original / 16:9 defaults. The native HTML camera picker cannot set iOS camera aspect ratio; RASD applies a centered crop after capture (16:9 landscape, 9:16 portrait). Full exports keep the maximum exact-ratio integer pixel rectangle without resampling; original bytes and annotation coordinates remain unchanged. An information strip adds height beyond the selected ratio. Crop and message field snapshots are included in note backups; legacy notes keep Original/all message fields.

`tests/framing-share.test.mjs` covers Kuwait time boundaries, selective message fields, legacy migration and backup validation. `tests/framing-browser.mjs` compares every exported pixel against the source crop for 4032×3024 and 3024×4032 inputs, checks pointer mapping to original coordinates, restores full dimensions, preserves original bytes, verifies mobile tool visibility, and tests persisted message selections, all-off behavior and share activation. Real iPhone capture and WhatsApp delivery remain device acceptance checks.

0.7: Edit combines markup and details; Preview stays read-only. No automatic cropping for new captures or imports, including devices that had a 16:9 default. Existing saved crops stay unchanged. Optional per-photo crop is explicitly labelled under Settings → Current photo; Apply defaults no longer changes framing. A 16:9 image imported from Apple Camera retains its supplied dimensions and exact source bytes. Native HTML capture cannot force the camera picker aspect ratio: https://www.w3.org/TR/html-media-capture/. Apple Camera itself supports the ratio: https://support.apple.com/en-euro/guide/iphone/iph3dc593597/ios.

Device settings use localStorage with no application expiry; notes use IndexedDB. Clearing website data or browser eviction can remove both; persistence is requested after saving a note but is not guaranteed. Use the Home Screen app and keep note backups outside RASD. Full backups include app-wide preferences/defaults; individual note backups do not. Sources: https://webkit.org/blog/14403/updates-to-storage-policy/ and https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/.

0.8: Information strip remains the new-photo default and uses warm paper, a note-first hierarchy, a category badge, and location/time icons. Portrait stacks metadata; landscape places it alongside the date when space permits. No coordinates are printed, including when no address is available. The optional on-photo layout uses a black gradient. Numeric dates use DD/MM/YYYY in Kuwait time; time remains h:mm AM/PM. Compact Google Maps URLs use `https://maps.google.com/?q=latitude,longitude` with unchanged coordinates; no shortening service or link backend. Both URL forms were verified against the same Google Maps pin in Chromium.

Settings uses grouped panels inspired by Apple Settings (https://developer.apple.com/design/human-interface-guidelines/settings and https://developer.apple.com/design/human-interface-guidelines/lists-and-tables). Dark is the default; Light is remembered locally and included in full backups. App appearance does not recolor exported photographs. Full backup works with an empty library. Limits remain 64 MiB and 500 notes; larger libraries need smaller note backups for now. Device camera/location permissions are controlled by iOS, not restored from the file.

Restoration validates the entire file and decodes every image before replacement. Notes and a pending configuration journal commit atomically in IndexedDB; settings replay is verified and the journal clears only afterward. An interrupted replay blocks edits and resumes at startup. Existing open windows receive a restore revision notification; stale library writes are rejected. Tests cover quota/transaction abort, partial localStorage writes, replay after reload, interrupted completion, v1 compatibility, empty/full config roundtrips and original byte equality. `tests/appearance-browser.mjs` covers theme persistence, responsive Settings, offline Arabic fonts and both export orientations.

If storage cannot be inspected at startup, RASD reports the limitation and offers a session-only camera/editor/export flow, with persistent changes disabled until reload. An observed unfinished restore remains gated. Full backup validation preserves distinct category IDs even if labels collide after legacy imports, and preserves valid legacy project text.

0.8.1: Printed typography scales with photo width, keeping the note approximately 17.5px and supporting details at least 12px when viewed at 390px wide. Notes/projects/categories use weight 600; metadata uses 500 with darker strip text. Arabic and Latin retain their reading direction but every row aligns left, including grouped header badges and compact metadata. The overlay starts fading above its content and ends at 72% black, with a gentle text shadow. Settings → Photo information → Address on photo selects Area, Block and Street independently; omitted components remain stored and WhatsApp message fields remain separate. Legacy notes without these flags print all available address fields. New choices apply to new photos; existing photos require Apply defaults. Tests verify address flag backup roundtrip and isolation across separate browser contexts.


0.9: Select existing arrows, circles and text to move, resize, recolor or delete them; edit selected text directly. Undo retains the last 100 annotation changes. Selection guides and unfinished gestures never enter exports or draft snapshots. Text scale survives save and backup.

Local drafts are separate from saved notes. Closing the editor flushes the current draft; Camera resumes the latest and Notes lists all drafts. Save note commits the note and removes its draft atomically. Discard confirms loss and leaves an existing saved note unchanged. Snapshots serialize, reject stale versions, and cannot restore a deleted note. Full restoration clears drafts with the saved library. Save or discard drafts before a full backup, so no unfinished work is silently omitted. Storage failures keep the live editor available for export; confirmed disposal works even if persistence was never available. No accounts, assignment or resolution workflow were added.

Draft verification covers offline recovery with original bytes, Arabic text while focused, cancellation during an autosave, multiple drafts, failed transactions, stale windows, discard recovery and storage-unavailable capture. Browser QA uses Chromium; native iPhone camera, Safari eviction and iOS termination behavior still require device testing.


0.10: Annotations default to direct selection, with touch handles for arrow endpoints, circle corners and text scale. Newly drawn objects select themselves; tapping selected text again opens an input on the photograph. One note can hold 1–10 originals (25 MiB each, 100 MiB total); each photo retains independent markup and framing. A thumbnail rail switches photos and offers Camera/Library additions and confirmed removal. Description, category, address and stamp settings are shared. Main Share exports every photo separately and respects the message setting; Photo actions can share/download the current photo. Exports are serialized, cached by photo and prepared before the share gesture. Unsupported multi-file sharing offers explicit per-photo actions, never silently drops the remaining images.

Category-specific Quick phrases append to existing note text. Settings supports adding, editing and deleting Arabic/English phrases (20 per category, 300 characters each). Full v3 backups include the phrase catalog, every original and per-photo edits; v1 note and v2 full backups remain readable. Current v3 files require this release or newer. Existing 64 MiB backup limit remains; no original is compressed to fit it.

The local database version advances to block old single-photo app windows from overwriting multi-photo records. Existing notes and drafts remain; update any older open RASD windows before using their saved library.


0.13: Fresh preferences use Dark and Information strip, printing location (Block/Street only), date and time. WhatsApp text includes the note, Block, Street and Maps link. Project/category are off in both; the photo note, message date/time and Area are off. Automatic address stays on. Existing saved preferences and notes keep their settings.

Safety and Site Cleanliness have the approved Arabic quick phrases; Site Works adds فرش طبقة ميلينق. Exact untouched English presets upgrade once; customized/deleted entries stay intact. Phrase-default version metadata is preserved in full backups, including deliberate preset deletions. Older two-category full backups remain readable. Visible capture/report metadata uses Date & time.


0.14 adds original video attachments, including video-only notes. Hold the main shutter for 400 ms to record with microphone access, release to finish; normal photo capture is retained. A native-video picker and video Library import are alternatives. Max 60 seconds / 50 MiB each, 10 attachments / 100 MiB originals per note. No video markup or burned-in stamp. Mixed sharing includes PNG photos and raw video files. PDF reports show labeled still previews, not playable video. DB v5 blocks old photo-only writers. Video backups use v4; photo-only backups remain v3, and legacy imports remain supported. Full backup size remains 64 MiB. The same release is prepared for this existing Site and for the portable GitHub Pages export.


0.15 prepares full-size files for multi-attachment notes only when the user asks to share or save an export. Saving a note or its draft persists the originals and edits without waiting for full-size encoding. The editor keeps a preview up to 1600 px on its longest side and uses the original for full-resolution export. Sequential encoding releases each full-resolution image before advancing. The share confirmation provides a fresh tap for the native share sheet. Quick phrases lists all groups with entries and applies the selected phrase’s category.
