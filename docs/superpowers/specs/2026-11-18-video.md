# Video observations

User requested video attachments and Snapchat-style hold-to-record from the camera. User explicitly chose unmodified video with note text and Maps link, rather than burning information into video. The current deliverable is the portable GitHub Pages source/ZIP; retain the existing 0.13.0 bundle and published host.

Tap still opens native photo capture, retaining supplied photo quality. Holding the shutter for 400 ms records from the live rear-camera stream with microphone permission; release stops and opens the resulting note. A first permission prompt must never start recording after the finger has been released. Provide an explicit native Record video fallback and import video from Library. Capture interruptions stop recording; failed/cancelled capture must not create or overwrite notes. Do not claim Safari device verification.

Notes may contain photos and videos, including video-only notes, with shared project/category/description/location. Preserve originals; video playback replaces the canvas for a selected clip. Markup/stamps/crop apply only to photos. Mixed sharing includes every attachment (PNG photos plus untouched videos), with existing explicit per-item fallback. Save & Next and drafts retain their existing contracts. Full and note backups include original video bytes; earlier backups remain readable and old writers are blocked. PDF reports include a labeled still preview for each clip and explicitly state that video is shared separately.

Implementation choices communicated to user: initial video cap 60 seconds / 50 MiB each; keep 10 attachments and 100 MiB total originals per note. Keep 64 MiB backup cap with clear failure, never truncate/compress files silently. Support browser-decodable MP4, QuickTime/MOV and WebM, detect recorder MIME support. No new runtime dependencies, backend, auth or cloud uploads. English UI, Arabic content, existing design.
