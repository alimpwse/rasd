# Video observations implementation plan

> For agentic workers: execute the bounded tasks below, use TDD for new behavior, and run integrated verification before packaging. The owner handles shared integration and the final handoff.

**Goal:** Add local original-video observations with hold-to-record and a portable GitHub Pages release.
**Architecture:** Retain the legacy `photos` array name as the ordered attachment collection; photo shapes remain unchanged, video entries carry kind/duration/dimensions. Keep recording and video decoding separate from app orchestration. Upgrade IndexedDB writer version and only require backup v4 when videos are present.
**Tech stack:** Existing static ES modules, MediaRecorder/getUserMedia, IndexedDB, native Web Share.
**Spec:** `docs/superpowers/specs/2026-11-18-video.md`.

## Global constraints

No runtime dependencies or server. Existing originals/settings/backups remain intact. Video is unmodified, max 60 seconds / 50 MiB each; all notes max 10 attachments / 100 MiB. Preserve photo quality, explicit update acceptance, local privacy, English UI and Arabic content. Work in isolated 0.14.0 export; do not publish or alter the previous host/bundle.

## Review focus

Permission resolves after release; interrupted/oversized/failed recording; malformed or unsupported videos in imports/backups; old-client overwrites and mixed-attachment data loss; stale async decode/share/restore results. Tests below cover these cases plus the full regression suite.

## Task 1 — Data contracts (bounded delegate)

Files: `dist/model.js`, `backup.js`, `storage.js`, new `tests/video-model.test.mjs`, relevant migration fixtures only.
Produces: `MAX_VIDEO_BYTES=50*1024*1024`, `MAX_VIDEO_SECONDS=60`, `isVideo(asset)` (kind video or video MIME), `mediaExtension(blob)`; video shape `{id,kind:'video',original,thumbnail,duration,width,height,annotations:[],crop:{ratio:'original'}}`. Existing `photosOf` returns all ordered attachments. Images retain existing shape. Normalize and validate no video markup/crop, finite positive metadata, duration <=60, dimension/pixel limits. v3 photo-only backups stay valid/output v3; video backups output v4 and read losslessly. IndexedDB v5 blocks older writers.
- [x] Write/run RED tests for video-only/mixed validation, exact original byte roundtrip, invalid metadata/type/size/annotations, old versions and rejected older-version video payloads.
- [x] Implement contracts and run GREEN plus full units. Do not touch app/editor/report or recorder files.

## Task 2 — Video capture/decoding (bounded delegate)

Files: new `dist/video.js`, `dist/video-capture.js`, new focused tests only.
Consumes Task 1 limits/helpers. Produces `inspectVideo(blob)` -> `{duration,width,height}` and `prepareVideo(blob)` -> complete video asset incl <=512KiB image thumbnail. Both reject unsupported, oversized, overlong, unreadable clips, clean object URLs/timeouts. Recorded WebM duration must be handled without trusting an invented duration.
Produces `HoldVideoCapture(button,{getStream,canStart,onPhoto,onVideo,onState,onError})`; `active` getter; `stop()` ends recording; `cancel()` discards/invalidate pending permission; `destroy()` cleanup. `onState({status,elapsed})` statuses idle/requesting/recording/finishing. `onVideo(blob)` is awaited before idle. 400ms hold, short click invokes onPhoto within native user gesture, long-press suppresses synthetic photo click. Clone preview track and acquire microphone; do not stop owner's preview tracks. Feature-detect MP4 first then supported WebM. 60s cap, byte cap, no recording after release/permission race, stop all owned tracks.
- [x] RED tests for gesture/permission/cancel/timing/byte-error/cleanup paths.
- [x] Implement GREEN with no app changes. Browser tests use synthetic stream where possible; report any real Safari limit.
